# Lab 7：輸出驗證器

> **目標**：用數據證明「改了 prompt 之後，失敗率真的下降了」。
> 做完你會有一張圖。那張圖就是這門課的結論。

## 這個 Lab 在做什麼

從一封自由格式的訂購 email，讓 LLM 抽出結構化的訂單 JSON。
然後用驗證器跑三層防線，統計它多常出錯、以及**錯在哪一類**。

```
emails/*.txt  →  LLM  →  JSON  →  validate.ts  →  通過 / 問題清單
                  ↑                     │
                  └──── v3 才有：把錯誤訊息餵回去 ────┘
```

## 開始之前

不用 `npm install`，Node 24 直接跑 `.ts`。

```bash
node run.ts --version v1 --n 10                 # 走 pi（預設）
node run.ts --version v1 --n 10 --backend mock  # 離線，不花額度
```

> ### ⚠️ 用 `--backend mock` 的話，先知道它怎麼評分
>
> 假模型是靠**關鍵字**判斷你的 prompt 有沒有變強的：
>
> | 它看到 | 就降低哪類錯誤 |
> | --- | --- |
> | `"unit_price"`（schema 貼進去了） | 幣別亂寫、缺 tracking_no |
> | `錯誤示範` / `不要這樣做` / `反例` | 算術錯誤 |
> | `只輸出` / `不要任何解釋` | code fence、開場白 |
>
> 所以**用英文寫、或用它沒認得的措辭，在 mock 下會看不到改善**——那是假模型的限制，不是你的 prompt 不好。
> 真模型不是這樣運作的。要看真實效果就不要加 `--backend mock`。

> **額度提醒**：整個 Lab 大約 40 次呼叫。先用 `--backend mock` 把流程跑順，
> 確定沒問題再換成真的模型。撞到 429 就先用 `--backend mock` 把流程跑完，不要乾等。

## 步驟

### 1. 先看基準線有多爛

```bash
node run.ts --version v1 --n 10
```

`v1` 是 `prompts.ts` 裡最爛的那一版：「幫我從這封信裡把訂單資料整理成 JSON。」

**看輸出的「失敗類型」那一段。** 失敗率是多少不重要，
**它都錯在哪一類**才是你接下來要修的東西。

### 2. 強化 prompt

打開 `prompts.ts`，只有 `V2` 需要你改，裡面有三個 TODO：

1. 把 `SCHEMA` 常數的內容貼進 prompt（給 schema 比用文字描述欄位有效得多）
2. 放一個**反例**——壞掉的輸出長什麼樣、以及它壞在哪
3. 寫死輸出規定（只能有 JSON）

```bash
node run.ts --version v2 --n 10
```

失敗率沒降？**先看失敗類型**：是哪一類沒被你的 prompt 處理到？

### 3. 加上重試迴路

```bash
node run.ts --version v3 --n 10
```

`v3` 用的 prompt 跟 `v2` 一樣，差別是驗證失敗時會把**具體的錯誤訊息**
接回去再問一次（最多兩次）。重試的邏輯在 `run.ts`，不用你寫。

### 4. 畫出來

```bash
node report.ts
```

會印出三個版本的對照表、失敗類型分布、平均 token 數，
並產生 `chart.svg`。

## 驗收

**基礎**　你有一張三個版本的失敗率對照，而且能解釋為什麼會這樣。

**如果失敗率沒有下降，那也是有效的結果。** 10 次的樣本波動很大，
免費模型雜訊更大。替代驗收：**你能分類出 3 種不同的失敗類型，並解釋每種為什麼會發生。**

**進階**　打開 `validate.ts` 最下面，自己補上至少兩條邏輯層規則。
想一想：還有什麼「每個欄位單獨看都合理，但合起來不對」的情況？

## 順便注意兩件事

**`report.ts` 會印出成本換算。** 平均 token 數 × 使用量 × 單價 = 這個功能一個月要花多少錢。
這是產品會議上第一個被問的問題，而多數人答不出來。

**有些錯，重試也修不掉。** 跑完 v3 之後看看剩下的失敗類型——
如果 `ship-before-order` 還在，那代表它**根本就把日期讀反了**，
而重試只是叫它「再輸出一次」，不會讓它重讀。
迴路修得掉格式與算術，修不掉理解錯誤。
