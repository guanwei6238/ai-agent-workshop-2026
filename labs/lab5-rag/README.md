# Lab 5：最小 RAG

> **目標**：讓它有能力回答節 1 開場那個它答不出來的問題。

## 先重現問題

```bash
node ask.ts "期末成果發表會每組報告幾分鐘？"
```

它會告訴你它沒有這份資料——**這是對的行為**。
但對產品來說，「不知道」跟答錯一樣沒用：使用者問了，你什麼都沒給。

> 用能力較弱的免費模型時，它可能反而會**編一個數字**。那更糟，
> 而且正好是下午節 4「驗證」要處理的問題。兩種結果都往下走一樣。

## 素材

`knowledge/club-handbook.md` 是一份社團手冊，裡面全都是模型
不可能知道的事實（報告 8 分鐘、器材借 3 天、鑰匙 4 副……）。

## 你要做的

打開 `retrieve.ts`，只有 `score()` 需要改。

現在的版本笨到沒用——它檢查「整句問題」有沒有原封不動出現在段落裡，
所以永遠檢索到 0 段。

把它改成關鍵字比對：

1. 把問題切成字詞（中文可以用 **2 個字為一組的滑動視窗**，很粗暴但意外有效）
2. 數有幾組出現在段落裡
3. 回傳命中數

改完之後：

```bash
node ask.ts --both "期末成果發表會每組報告幾分鐘？"
```

`--both` 會把「沒檢索」跟「有檢索」的答案並排印出來。

## 驗收

**基礎**　你能展示同一個問題的兩種答案，而且第二種是對的。

多試幾個問題：

- 器材可以借幾天？
- 社辦鑰匙有幾副？
- 單筆支出超過多少要開社員大會？
- 社團專案的補助上限是多少？

## 進階：關鍵字檢索的極限

試試這兩個問題：

```bash
node ask.ts --rag "器材可以借幾天？"
node ask.ts --rag "缺席太多會怎樣？"
```

看一下它檢索到哪幾段、分數多少。你會發現**正確的段落跟錯誤的段落分數一樣高**。

原因：關鍵字比對只看**字面**。手冊裡寫「借用期限」，你問「可以借幾天」，
字面上只重疊了一個「借」字。

**進階題**：改成 embedding 檢索，比較兩者在這類問題上的差異。

> ⚠️ 免費模型不一定提供 embedding。如果沒有，改用 TF-IDF 或 BM25
> ——一樣是純本地、不用呼叫 API，而且已經比 2-gram 好很多。
> 重點不是用哪個演算法，是**看見「字面比對」的極限在哪**。
