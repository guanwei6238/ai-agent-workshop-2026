# Lab 1：用 agent 做一個真的功能

> **目標**：體感「派工」跟「問答」的差別，並且**看清楚它到底做了什麼**。

## 素材

`habit/` 是一個能跑的小 CLI。它的風格很明確——你等一下要看的，
就是 agent 有沒有跟上這個風格。

先花 3 分鐘把它跑起來、翻一下 `src/`：

```bash
cd habit
node src/cli.ts list
node src/cli.ts done 運動
```

## 步驟

### 0. 先變成 git repo

```bash
cd habit
bash init.sh
```

這樣等一下才能用 `git diff` 看 agent 改了什麼、用 `git checkout .` 還原。

### 1. 開 pi，選模型

```bash
pi
```

進去之後打 `/model`，選 `mimo-v2.5-free`。

> **用互動模式，不要用 `pi -p`。** 互動模式會顯示它呼叫了哪些工具、
> 讀了哪些檔、跑了什麼指令——那正是 agent 跟網頁版最不一樣的地方，
> 也是這個 lab 要你看的東西。

### 2. 丟一個需求

**用你平常跟網頁版講話的方式就好**，不要刻意講清楚。

| 需求 | 說明 |
| --- | --- |
| **`streak` 指令**（推薦） | 顯示每個習慣目前**連續**達成幾天 |
| `remove` 指令 | 刪掉一個習慣 |
| `stats` 指令 | 顯示最近 7 天的完成率 |

### 3. 看著它做

它讀了哪些檔？跑了什麼指令？改了幾次才說完成？

### 4. `git diff` 逐行看

```bash
git diff
node src/cli.ts streak
```

**這一步是整個 Lab 的重點。** 不要只確認「功能會動」，要看它**怎麼**做到的。

> **看著它做，不等於知道它做了什麼。**
> 畫面上跑過去的是它想讓你看到的摘要；`git diff` 是它實際做了什麼。
> 它會說「已新增 streak 指令」，但不會說它順手改了 `ui.ts`。

### 5. 填觀察記錄表

打開 `../observation-sheet.md`，填第一欄。

### 6. 再來一次，這次講清楚

```bash
git checkout .        # 還原程式碼
./reset.sh            # 還原資料
```

用**同一個需求**再跑一次，但這次把要求講明白（風格、放哪裡、要不要處理錯誤……），
填記錄表的第二欄，比較兩次。

## 驗收

**基礎**　專案多了一個能跑的功能，而且你的記錄表填得出來。

**進階**　同一個需求、同一句話，**再跑一次**，比較兩次的結果差多少。
這就是「同樣輸入不保證同樣輸出」的實測。

## 提示

如果你不知道要看什麼，先看這幾個地方：

- 它把新檔案放在 `src/commands/` 裡嗎？還是塞進 `cli.ts`？
- 它有沒有記得在 `cli.ts` 的指令表註冊？
- 它印東西是用 `ui.ts` 的函式，還是直接 `console.log`？
- 它算日期是用 `date.ts` 的 `shift` / `diffDays`，還是自己重寫一套？
- 它的註解是中文還是英文？
- 它有沒有用 `any`？
- 錯誤處理是 `fail()`，還是 `throw new Error` 或直接 return？
